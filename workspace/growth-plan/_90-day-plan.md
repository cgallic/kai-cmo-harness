# Kai Marketing OS 90-Day Plan

## Strategy

Win a narrow wedge first: Claude Code users, AI builders, indie SaaS founders, and agencies who already believe agentic workflows belong in the repo.

The promise:

**Turn your repo into a marketing workspace that can plan, write, gate, and log growth work.**

The proof:

- Install in 5 minutes
- Run `/kai-growth-plan`
- Produce a strategy package from the actual repo
- Run quality gates
- Leave a reusable `MARKETING.md` and workspace outputs behind

## Month 1: Tighten The Story And Ship The Demo Loop

Focus: turn curiosity into first runs.

P0: Fix the message spine

- Choose one public product name for the repo: **Kai Marketing OS**
- Keep "Kai CMO Harness" as the repo/package name where needed
- Standardize inventory counts across `README.md`, `MARKETING.md`, `AGENTS.md`, and `llms.txt`
- Rewrite the first screen around "repo-native marketing OS"

P0: Publish the artifact loop

- Add a 3-minute demo: clone repo, run `/kai-start`, get `MARKETING.md`, run `/kai-growth-plan`, open the generated plan
- Add screenshots or terminal captures of a real output
- Add a `/workspace/growth-plan` sample as proof alongside claims

P1: Make the GitHub repo convert

- Add a "Start here" block with three paths: founder, agency, developer
- Add a "What this is not" section: not a chatbot, not a prompt pack, not an autopublisher
- Add one short comparison table: blank chat vs prompt library vs Kai

P1: Founder-led launch content

- Publish a launch essay: "The repo is the missing marketing context"
- Publish a technical post: "How to build marketing skills that do not hallucinate ad policy"
- Publish a demo thread on X and LinkedIn

Expected outcome:

- More GitHub stars from the right audience
- More installs from Claude Code users
- Clearer category comprehension in under 5 seconds

## Month 2: Build Distribution Around One Repeatable Use Case

Focus: show useful work, not feature lists.

P0: Pick one flagship workflow

Recommended flagship:

**Run `/kai-growth-plan` on any SaaS repo and get a 90-day marketing plan with gates and routing.**

This workflow is broad enough to attract founders but specific enough to demo.

P0: Create a content series

- "I ran Kai on 10 indie SaaS repos. Here is what every one was missing."
- "The marketing file every repo should have"
- "Claude Code skills for marketing: what belongs in the repo"
- "How to stop AI marketing from publishing weak claims"

P1: Community seeding

- Share concrete repo examples in Claude Code, indie hacker, SaaS, and agency communities
- Offer teardown threads: "Drop a repo, I will run Kai and share the first 5 fixes"
- Turn each teardown into a case-style artifact with permission

P1: Partnership targets

- Claude Code educators
- AI builder newsletters
- SaaS boilerplate maintainers
- Small agency operators
- Dev-tool communities

Expected outcome:

- First repeatable acquisition channel
- Customer-language evidence for positioning
- A queue of real repos to run and improve the product against

## Month 3: Turn Usage Into Proof

Focus: convert runs into proof and proof into distribution.

P0: Add a shareable output format

Every successful run should create a portable artifact:

- `MARKETING.md` badge or summary block
- `workspace/growth-plan/_executive-summary.md`
- Quality report showing gates passed
- "Generated by Kai Marketing OS" footer in example docs, optional for users

P0: Publish case studies

Case study format:

- Before: repo had no marketing context
- Run: command and inputs
- Output: plan, page, email, campaign, or audit
- Gate: quality result
- Next action: what the operator did after the run

P1: Add lead capture

- GitHub README CTA: join beta, book setup, or request a repo teardown
- MeetKai site CTA: "Get a Kai run on your repo"
- Email capture tied to a useful template: "The MARKETING.md starter kit"

P2: Start measured AI-search presence

- Create entity pages for Kai Marketing OS, `/kai-growth-plan`, and repo-native marketing OS
- Add current `llms.txt` with consistent counts
- Publish comparison and "best tools" content only with clear evidence and no fake rankings

Expected outcome:

- A compounding artifact loop
- Early proof that Kai can create useful marketing work from real repos
- A stronger base for Product Hunt, HN, or a broader public launch
